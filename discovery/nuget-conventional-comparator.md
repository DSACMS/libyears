# Conventional NuGet version-age comparator — 006-0030

Narrow prospective investigation. Frozen predecessor 006-0029 is preserved in
830a19c; its historical recommendation is not rewritten. This investigation asks
whether a deliberately selected public reference policy can support a narrower
age claim, rather than proving an effective restore namespace or acquisition.
Review dispositions and exact freeze identity belong in the companion review.

## Decision and claim

Recommend a conventional nuget.org comparator ONLY when bounded repository
inspection establishes no relevant contrary assignment or unresolved ambiguity.
This is a product reference policy, not an observed identity relationship:
“For this qualified current snapshot, compare the selected version with
nuget.org's public release history by convention.” Namespace correspondence is
assumed by this disclosed policy, not independently established. Public results
are dates in that selected history; public existence never authorizes the query.
Do not say applicable namespace was proven, or that packages were acquired from
nuget.org. Actual acquisition/content/producer/evaluated/deployed state remains
unestablished. User/machine/ancestor configuration outside the scan boundary is
not inspected or reconstructed; the convention is deliberately repository-bounded.

The initiating human explicitly proposes a PRODUCT COMPARATOR POLICY with
population/selection already established, absence of repository contrary evidence
and ambiguity, and independent review before continuation. That supplies policy
selection authority if review supports this qualified claim; NuGet documentation
alone cannot select the product metric. A different requirement to establish the
actual namespace relationship would still require positive mapping/testimony.

## Upstream evidence and inference

[Configuration hierarchy](https://learn.microsoft.com/en-us/nuget/consume-packages/configuring-nuget-behavior)
means repository silence cannot establish effective host sources. This remains a
limitation, rather than a veto on a consciously repository-bounded convention.
[Source mapping](https://learn.microsoft.com/en-us/nuget/consume-packages/package-source-mapping)
selects eligible feeds by package identity and specificity. Enabled alternate feeds
without assignment supply a concrete competing-history possibility. The
[config reference](https://learn.microsoft.com/en-us/nuget/reference/nuget-config-file)
does not assign priority from PackageReference source order.
[Restore properties](https://learn.microsoft.com/en-us/nuget/reference/msbuild-targets#restore-properties)
can override or augment sources; unsupported/computed relevant policy is not silence.
[Catalog dates](https://learn.microsoft.com/en-us/nuget/api/catalog-resource)
remain first receipt by the selected source, with all existing identity/date/listing
requirements. None of these sources proves conventional reference correspondence;
the inference is that an explicitly disclosed reference policy can yield an honest
conditional age while retaining that limitation.

## Contrary evidence and precedence

Validate explicit accepted testimony fully; invalid supplied testimony cannot be
ignored. Known contradictory assignment always wins over weaker public evidence.
Supported unique public mapping can disambiguate otherwise mixed eligible feeds;
private, multiple winning, unresolved or unmapped results cannot fall through.
Accepted testimony may establish exact P/V namespace where repository eligibility
alone is ambiguous; eligibility is not contradictory assignment. Private testimony
or testimony conflicting with positive assignment refuses. When there is no such
positive authority, apply convention only after complete bounded silence/public
policy inspection; unknown relevant syntax refuses.

“Closed” mapping means supported source/mapping sections reset inherited relevant
settings, keys resolve and the unique most-specific winner is enabled. Ordinary
source clear alone does not prove host closure (006-0029 machine-default finding).
Initial implementation may safely support a strict subset and refuse unsupported
policy, provided unknown is not mislabeled private or absence.
