## Verification and next gate

Independent read-only verification reproduces the retained analysis/inventory;
checks every frozen body, identity, URL/edge binding and actual budget; and repeats
the original 127-row trace/39 partition/exact42 preservation. Small synthetic
checks discriminate model type, child property override, cyclic/unavailable/env
expansion and BOM-own-context separation. These are disposable analysis checks,
not production intake tests or a Maven semantic oracle. An initial offline-harness
attempt blocked its own Git directory lookup under the audit guard; it was fixed
to reuse the already-resolved directory. No product failure or network occurred.

Keep applicability acceptance, present public retrieval, comparator permission
and age-date evidence separate. No comparator/source policy is revalidated or
weakened; supplied management and public coordinates do not grant a measurement
capability. Private policy and unknown relevant semantics must still refuse.
This is neither an effective POM nor a resolved graph, historical acquisition
witness, current build completeness proof or measured-yield result.

**Disposition: needs more technical evidence; defer intake specification.** The
smallest next evidence step is a consumer-context-first closure completion study
using the frozen corpus, the ten identified additional exact documents and any
newly supported parent/import edges within a separately bounded grant (or explicit
supplied bytes), plus narrow pinned authoritative composition-source inspection.
The list is not promised complete; a higher cap alone does not prove feasibility.
No policy decision to waive closure is proposed. Only after supported positive
field recovery is demonstrated should the human select a restricted supplied-
evidence intake for specification; automatic public acquisition would be a
separate product/disclosure choice. This run stops before either selection.
